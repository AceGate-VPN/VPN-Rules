# 自动同步券商规则

- 日期：2026-07-22
- 任务类型：实现
- 目标：通过 GitHub Actions 自动将上游生成仓库中的 5 个券商规则同步到 `AceGate-VPN/VPN-Rules`。

## 已确认合同

- 生成源为公开仓库 `OyaTechnology/AceVPN-Rules` 的 `master` 分支。
- 同步范围固定为 `Futu`、`Longbridge`、`TigerFintech`、`Schwab`、`HKBroker`。
- 源仓库当前使用 `Rules/site`，目标仓库使用 `rules/site`；脚本读取实际目录项名称，因此兼容大小写敏感和不敏感文件系统。
- JSON 顶层必须严格符合现有 `main.go` 输出的 `{"rules": [...]}` 结构。
- Leaf 校验入口将 `rules` 反序列化为 `Vec<leaf::config::json::Rule>`；同步脚本按该结构校验已声明字段的类型，并保留现有 `process_name` 扩展。

## 实现

- `scripts/sync-broker-rules.mjs`：读取源仓库、执行文件白名单同步、校验结构和 IPv4 CIDR。
- `.github/workflows/sync-broker-rules.yml`：每日 UTC 02:17 定时运行，也支持手动触发。
- Workflow 使用目标仓库自带的 `GITHUB_TOKEN` 提交，无需跨仓库写权限或额外 PAT。
- 仅当 5 个目标文件产生差异时提交；提交前检查暂存区白名单并执行 `git diff --check`。
- 同步采用普通文件提交，不合并两个仓库的 Git 历史。

## 验证

- 公开源真实检出：`OyaTechnology/AceVPN-Rules@865012111c7567763adffcfb88e2d945864cfcf5`。
- `node --check scripts/sync-broker-rules.mjs`：通过。
- 真实源同步：`校验文件数=5`、`更新文件数=0`，目标内容与当前规则逐字节一致。
- 当前 Leaf 源码构建出的 `leaf_test_rule_format`：5 个文件全部通过，`failed=0`。
- Workflow YAML 解析：通过；内嵌 Bash 使用 `bash -n` 检查：通过。
- `git diff --check`：通过。
- 本地没有安装 `actionlint`，未执行其专用语义检查；YAML、脚本和真实同步路径已分别验证。

## 风险与回滚

- 源仓库不可访问、目录大小写同时存在、文件缺失或格式不兼容时，Workflow 会失败且不会提交部分结果。
- `process_name` 来自现有 `main.go` 输出，但当前 Leaf JSON `Rule` 未声明该字段，serde 会忽略它；该字段不会造成反序列化失败，但其路由语义不会生效。
- GitHub 定时任务不保证精确到分钟；手动触发可立即同步。
- 回滚方式：revert 引入同步脚本和 Workflow 的提交，不需要改写分支历史。
